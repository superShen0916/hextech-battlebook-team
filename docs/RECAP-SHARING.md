# 当晚与多人回顾分享

源码位于唯一前端的`src/RecapStudio.tsx`、`lib/recap-share.ts`和`lib/recaps.ts`。

## 使用

在大厅“当晚战报”或“多人共同回顾”选好玩家、日期/范围，有有效同队记录时点“分享这份回顾”。弹窗提供PNG下载、手机长按保存，以及复制回顾链接；原复制摘要功能保留。

- 图片为 1080 宽的竖版长图：品牌头、日期与视角、场次与环形胜率、逐场胜负格、带名次与分级色带的车队鉴定、成员双列数据（最多 8 人）、最近 3 场、页脚口径。宽度之外高度按内容自动计算，不裁切区块；长句按宽度换行。
- 当晚链接保存视角玩家、开场日期和周五过滤。
- 多人链接保存2—5位稳定公开id及全部/30/90天范围。原应用链接保留访问sharecode，清除会误入个人页的player等参数。
- 分享链接沿用打开页面的域名。在正式WorkBuddy网站打开并复制，链接使用`https://hextech-battlebook.app.workbuddy.host/`与访问码；本机预览中的`127.0.0.1`链接仅供本机测试，不是对外地址。
- 链接打开大厅并定位到回顾，恢复所选条件。日期/成员不可用时明确提示，不把另一份回顾冒充分享内容。
- 图片保留生成时结果；链接按站点当前已发布数据和所选范围重新计算，后续补局或时间推移可能改变数字。
- 同队样本提供“上等马／中等马／稳住位／下等马／轮换位”梗卡，差战绩满足明确条件才追加“甲级战犯”；网页、摘要与PNG共用同一统计模型。完整规则见 [每周与氛围说明](WEEKLY-EXPERIENCE.md)。

## 统计规则

当晚按北京时间18:00至次日06:00，凌晨归前一天；至少两位已收录朋友同队。当晚视角统计该玩家这一晚全部同队场次，各人按自己上场的场次算场均，样本不足主力一半的标“轮换位”不参与排名；多人取所选全部玩家在同一队的有效交集，区分对手，不将同队视为真实预组队。评分、荣誉20/30门槛和个人数据口径不因分享变化。

## 本周最胡

大厅「高光回顾」顶部展示「本周最胡」卡片：本周伤害占比最高的三局各占一张，按占比从高到低排列，同一局只占一个名额。卡片列出这局的装备，以及海克斯的图标和名称。点击玩家名称可打开档案。

- 口径：本周单局伤害占本队五人合计最高——本人该局伤害 ÷ 本队五人伤害合计。同队恰好五人、五人伤害都是非负有限数字且合计大于 0 才参评；队伍人数不足或伤害缺失的局整局跳过，不用 0 顶替，也不跨队合并。
- 本周 = 北京时间周一 00:00 至下周一 00:00（与 `haido/rating_lp.py` 的 `week_start_ms`/`WEEK_MS` 同一切法），进行中的周只统计到本次构建的截止时刻 `as_of`。卡片固定指本周，与页面上选的日期/范围无关。
- 候选只含已建档名册，也就是现在拉战绩的这些人；不在名册里的路人哪怕伤害占比更高也不进榜。
- 并列规则：伤害占比降序 → 本局伤害绝对值降序 → 开局时间降序 → 公开 id 字符串升序。
- 数据写在 `/api/recaps/index.json` 的 `roided` 字段，是长度 0—3 的数组：本周按上面的并列规则排出的前三局，一局一条，没有候选时为空数组；每条附带 `match_id` 便于跳到那局战报，第一条与早期只取一条时的结果完全一致。装备 7 格、海克斯 6 格的空格保留为 `null`，缺的字段省略而不是补零。
- 这是战绩玩梗的趣味榜单，不是官方奖项，也不评输赢责任。

## 加载与失败恢复

回顾请求（含JSON响应体读取）20秒超时，超时或失败清除该请求缓存，避免一直加载。普通重试清空回顾缓存再读；版本混用时“刷新页面重试”保留可恢复的筛选并刷新整页。晚到的旧失败请求不能清掉已经成功的新缓存。

PNG由浏览器canvas绘制，不额外请求外部头像或上传战绩；生成和复制都是用户在页面中主动点击，不自动向朋友发送消息。

## 验证

`verify-recaps.mjs`覆盖原2—5人交集、当晚视角取出全部同队场次、短样本标轮换位不排名、胜率过半不给下等马、链接条件往返/访问码/非法成员与日期、分享图统计模型/顺序、网络与响应体挂起超时、失败重试和缓存替换竞态；构建还保留原7项前端检查及完整数据门禁。

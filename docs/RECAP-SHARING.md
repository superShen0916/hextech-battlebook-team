# 当晚与多人回顾分享

2026-10-24新增，源码在唯一前端的`src/RecapStudio.tsx`、`lib/recap-share.ts`和`lib/recaps.ts`。实际本机/线上状态见根STATUS。

## 使用

在大厅“当晚战报”或“多人共同回顾”选好玩家、日期/范围，有有效同队记录时点“分享这份回顾”。弹窗提供PNG下载、手机长按保存，以及复制回顾链接；原复制摘要功能保留。

- 图片展示当前筛选内的场次、胜负、胜率、最长连胜、最近50场结果、成员KDA与MVP/ACE、最近3场。夜晚最多展示8位成员，并明确标注截取；统计仍用当前筛选的完整样本。
- 当晚链接保存视角玩家、开场日期和周五过滤。
- 多人链接保存2—5位稳定公开id及全部/30/90天范围。原应用链接保留访问sharecode，清除会误入个人页的player等参数。
- 分享链接沿用打开页面的域名。在正式WorkBuddy网站打开并复制，链接使用`https://hextech-battlebook.app.workbuddy.host/`与访问码；本机预览中的`127.0.0.1`链接仅供本机测试，不是对外地址。
- 链接打开大厅并定位到回顾，恢复所选条件。日期/成员不可用时明确提示，不把另一份回顾冒充分享内容。
- 图片保留生成时结果；链接按站点当前已发布数据和所选范围重新计算，后续补局或时间推移可能改变数字。
- 新增同队交集的“上等马／中等马／下等马”梗卡，差战绩满足明确条件才追加“甲级战犯”；网页、摘要与PNG共用同一统计模型。至少3场且不混入换队友后的不同样本，完整规则见 [每周与氛围说明](WEEKLY-EXPERIENCE.md)。

## 不变的统计规则

当晚按北京时间18:00至次日06:00，凌晨归前一天；至少两位已收录朋友同队。多人取所选全部玩家在同一队的有效交集，区分对手，不将同队视为真实预组队。评分、荣誉20/30门槛和个人数据口径不因分享变化。

## 加载与失败恢复

回顾请求（含JSON响应体读取）20秒超时，超时或失败清除该请求缓存，避免一直加载。普通重试清空回顾缓存再读；版本混用时“刷新页面重试”保留可恢复的筛选并刷新整页。晚到的旧失败请求不能清掉已经成功的新缓存。

PNG由浏览器canvas绘制，不额外请求外部头像或上传战绩；生成和复制都是用户在页面中主动点击，不自动向朋友发送消息。

## 验证

`verify-recaps.mjs`覆盖原2—5人交集、链接条件往返/访问码/非法成员与日期、分享图统计模型/顺序、网络与响应体挂起超时、失败重试和缓存替换竞态；构建还保留原7项前端检查及完整数据门禁。实际浏览器与图片验收结果见根STATUS。
